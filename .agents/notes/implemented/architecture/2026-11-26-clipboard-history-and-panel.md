# Agent Note: Encrypted clipboard history with an in-memory FTS5 index in the agent, not an on-disk FTS5 index or an IME-side monitor

Status: implemented

## Problem

M3（Issue #10）要求类 Raycast 的剪贴板历史：`⇧⌘V` 或 v 模式 `v2` 打开面板，搜索中文与英文，回车粘贴回原 App。剪贴板是整台机器上最敏感的数据流：密码管理器复制的口令、安全输入（密码框）里的复制、`sk-…` API 密钥、私钥都会经过它。约束：IME 零 TCC（AGENTS.md 规则 1），剪贴板过滤与 `changeCount` 事务（规则 3）；macOS 26 的剪贴板访问权限（`NSPasteboard.accessBehavior`，15.4+）会对程序读取弹出询问；`unicode61` 分词器把一串汉字当成一个词，`你好世界` 搜不到 `你好`；FTS5 查询语法（`OR`、`NEAR/5`、`"`、`*`、`:`）直接拼接会注入或抛 `SQLITE_ERROR`；复制的图片可能是解压炸弹。

## Decision

- **进程与模块**：只有 launchd 管理的 `NoemaAgent` 运行剪贴板历史（单一写者，standby 实例不启动）。新目标 `NoemaClipboardCore`（只依赖 `NoemaCore` 与系统 SQLite、CryptoKit、Security、ImageIO）只被 `NoemaAgentCore`/`NoemaAgent` 链接；`check-imports.sh` 禁止 IME 可达目录导入它，并禁用 `SecItem*`、`AXIsProcessTrusted*`、`CGEventPost`/`CGEventSource`/`CGEvent(keyboardEventSource:)`、`CGPreflight*EventAccess`、`RegisterEventHotKey`。
- **先元数据后数据**：`PasteboardMonitor` 每 400 ms 只读 `changeCount`；新值先写入 `lastSeenChangeCount`，再判断。安全输入期间只记数并把该 `changeCount` 记入有界 taint 集，离开密码框后永不回溯捕获。随后 `ClipboardPrivacyFilter`（纯函数，无 AppKit）按序判定：安全输入 → 自写回（`ignoredSelfChangeCounts` 或 `dev.noema.clipboard.self-paste`）→ 隐私标记（`org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType`、`de.petermaurer.TransientPasteboardType`、`com.typeit4me.clipping`、`Pasteboard generator type`、`com.agilebits.onepassword*`、`com.1password.*`，检查剪贴板级与每个条目的类型）→ 来源 App 黑名单（12 个内置密码管理器 + 设置里的自定义项，大小写不敏感）→ 只有文件 URL（Finder 复制只记文件名文本，不读文件、不记图标）。只有 `.capture` 才调用 `readString`/`readData`。`accessBehavior == .alwaysDeny`、锁屏、睡眠、钥匙串锁定时不读取；恢复时把当前 `changeCount` 作为新基线。
- **自写回三层防环**：`prepareForNewContents(with: .currentHostOnly)`；条目同时写 `org.nspasteboard.TransientType`（空）与 `dev.noema.clipboard.self-paste`（UUID），让其他剪贴板管理器也跳过；返回前同步登记产生的 `changeCount`（最近 32 个）并推进 `lastSeenChangeCount`，即使第三方剥掉自定义类型也不会回环。
- **静态加密**：主密钥是登录钥匙串里的通用密码（服务 `dev.noema.agent.clipboard`，账户 `master-key-v1`，不同步），不用 Data Protection 钥匙串，所以 `NoemaAgent.entitlements` 保持空字典、不会遇到 `-34018`。只有 `errSecItemNotFound` 才生成新密钥；`errSecInteractionNotAllowed`/`errSecAuthFailed` 等映射为 `.keychainLocked`：拒绝写入、列表为空、绝不明文、绝不覆盖旧密钥，解锁屏幕后 `retryUnlock()`。`ClipboardCipher` 用 HKDF-SHA256 派生三把域分离密钥（文本 AES-GCM、图片 AES-GCM、去重 HMAC），每次封装用新的 96 位随机 nonce，AAD 绑定 `noema.clip.v1|text|<id>|<dedup>`、`|blob|<digest>`、`|thumb|<digest>`，密文换行或换文件即解密失败。标准与敏感条目一律加密；`classifySensitivity` 识别的 PEM 私钥、`sk-`、`ghp_`、`github_pat_`、`AKIA`、`xox?-` 在面板里默认遮挡，15 分钟后过期（普通条目 30 天）。
- **存储**：`~/Library/Application Support/Noema/clipboard/`（`0700` 实目录，`lstat` 拒绝符号链接）下的 `clipboard.sqlite`（`SQLITE_OPEN_NOFOLLOW`、`0600`、WAL、`secure_delete`、`foreign_keys`）只有元数据与密文列，没有任何 FTS 表。图片存为 `blobs/<digest>.enc` 与 `.thumb.enc`（`O_CREAT|O_EXCL|O_NOFOLLOW` 临时文件、`fsync`、`rename`、目录 `fsync`），磁盘上没有 PNG 头。`digest` 是去重 HMAC（64 位小写十六进制），不是明文 SHA-256，因此文件名不能用来确认某张已知图片被复制过。`(kind, dedup_hmac)` 唯一：重复复制只刷新 `last_used_at` 与来源；`image_blobs` 由 `ON DELETE RESTRICT` 保护，最后一个引用删除时才删文件；启动时回收孤儿。`maxItems` 2000、单图 25 MiB、图片总量 200 MiB，按最近使用淘汰未固定条目；固定条目不过期、不被淘汰。
- **搜索**：打开与解锁时把可解密的行装入 `:memory:` FTS5（`unicode61 remove_diacritics 2`），插入、去重、删除、过期、淘汰时同步更新；单行解密失败只计数跳过。`ClipboardTokenizer.indexForm` 在每个汉字、假名、谚文音节两侧加空格；`compileFTSQuery` 把 CJK 连续段编成短语（`"你 好"`，相邻且有序，所以 `世你` 不命中），其余词编成带引号的前缀项（`"swift"*`），全部 `AND` 连接，`"` 双写；用户输入永远不是 FTS5 语法。
- **图片**：先检查原始字节上限，再只读头部尺寸（PNG 直接读 IHDR，其他格式用 `CGImageSourceCopyPropertiesAtIndex`），单边 ≤ 16384、总像素 ≤ 6400 万，然后才解码；优先 `public.png`，TIFF/JPEG/HEIC 转成 PNG；缩略图用 `CGImageSourceCreateThumbnailAtIndex`（512 px）。
- **面板与粘贴**：`ClipboardPanelController` 是 borderless、`.nonactivatingPanel`、可成为 key 但不成为 main 的浮动 `NSPanel`（Liquid Glass，降低透明度时用 HUD 材质），打开前记下前台 App（排除 Noema 自己）。Esc 恢复原 App 焦点、点击外部只隐藏，两者都不碰剪贴板；关闭时清空解密缓存并重新遮挡敏感项。回车：自写回 → `AccessibilityPasteService`。未授权辅助功能时只重新激活原 App、零 `CGEvent`，提示“已复制到剪贴板，请按 ⌘V 粘贴”；已授权时最多等 150 ms（15 ms 步进）原 App 成为前台，期间其他 App 抢到前台或安全输入开启即中止，否则以 `.combinedSessionState` 源向 `.cgAnnotatedSessionEventTap` 发 `⌘V`。授权提示只在用户点按钮时请求。全局热键用 Carbon `RegisterEventHotKey`（零 TCC），退出与 `SIGTERM`/`SIGINT` 时注销热键、停止监视、关闭存储（WAL checkpoint）。

## Alternatives considered

- **磁盘上的 FTS5 表（含 `content=` 外部内容表或 trigram 分词）**。Rejected：FTS5 的倒排索引、`%_content`、`%_docsize` 把明文词元写进 `clipboard.sqlite` 与 WAL；加密 payload 却留下可还原原文的索引等于没有加密。trigram 分词需要至少 3 个字符，单字、双字中文搜索落空。内存索引在每次打开与解锁时解密重建（每条最多索引前 32768 个字符），换来磁盘零明文。
- **Data Protection 钥匙串（`kSecUseDataProtectionKeychain`）**。Rejected：需要 `keychain-access-groups`/application-identifier 授权，ad-hoc 与 CI 构建会得到 `-34018`（`errSecMissingEntitlement`），而规则 5 要求空授权签名。登录钥匙串项由创建它的已签名 App 拥有，锁定时返回 `errSecInteractionNotAllowed`，正好映射为 `.keychainLocked`。
- **`CGEventTap` 或 `NSEvent.addGlobalMonitorForEvents` 实现 `⇧⌘V`**。Rejected：都需要“输入监控”或辅助功能 TCC，且事件 tap 能看到所有按键；`RegisterEventHotKey` 零权限、只收到注册的组合键。
- **在 IME 里监听剪贴板或执行粘贴**。Rejected：违反规则 1，并把剪贴板权限与密钥绑在每个前台 App 都加载的进程上。IME 只发 `quickActionRequested(.clipboard)`。
- **始终用辅助功能（AX）`AXUIElementSetAttributeValue` 直接写入选区**。Rejected：很多 App（Electron、终端、游戏）不支持可写选区，且要求同样的辅助功能授权；`⌘V` 走目标 App 自己的粘贴路径，行为与用户手动粘贴一致。
- **明文 SHA-256 作为图片文件名与去重键**。Rejected：磁盘上的明文哈希能确认某张已知图片（截图、证件照）是否被复制过；改用去重 HMAC 不改变去重与引用计数语义。
- **只加密敏感条目**。Rejected：启发式必然漏判（未标记的口令、身份证号），全量加密的成本只是每条一次 AES-GCM。

## Consequences

- 验收：标记类型（剪贴板级与条目级）、12 个密码管理器与自定义 Bundle ID、安全输入期间复制后离开密码框、被过滤的复制 `readString`/`readData` 调用为 0；自写回即使第三方剥掉类型也不回环；`clipboard.sqlite`、`-wal`、`-shm`、`blobs/*` 原始字节扫描中明文与 `\x89PNG` 均为 0 次；1 字节翻转、跨行交换密文、错误密钥均解密失败且只计数；钥匙串锁定时零写入、不换密钥、`retryUnlock()` 恢复；`你`、`你好`、`你好世`、`你好 swift` 命中，`世你` 不命中，`"`、`*`、`OR`、`NEAR/5`、`foo:bar`、`(((` 零 SQLite 错误，删除与淘汰后立即搜不到；20000×20000 伪造 PNG 头在解码前被拒；TIFF 转 PNG；固定图片不被淘汰；TTL 保留固定条目；目录、数据库、WAL、blobs 目录的符号链接被拒；未授权辅助功能零 `CGEvent`，激活后安全输入开启零 `CGEvent`，目标前台时发出 `⌘V`。
- 实测（macOS 26.6.2，系统 SQLite 3.51.0 启用 `ENABLE_FTS5`）：ImageIO 对 IDAT 损坏的伪造 PNG 不返回像素尺寸属性，只靠 `CGImageSourceCopyPropertiesAtIndex` 会把炸弹误报为普通解码失败，所以 PNG 先直接解析 IHDR。
- 测试：`NoemaClipboardCoreTests`（过滤器、分词与查询、CryptoKit、钥匙串状态映射用假后端、图片、真实磁盘存储）与 `NoemaIPCTests/ClipboardAgentTests`（间谍 `PasteboardReading`、间谍 `AccessibilityPasteDriver`、控制器端到端、面板属性、热键）均不触碰用户钥匙串。负控：删除 `ConcealedType`、安全输入判断前移到推进 `lastSeenChangeCount` 之前、过滤前先读 payload、AAD 去掉 id、`indexForm` 不再切分 CJK、去掉尺寸检查、去掉激活后的安全输入检查，对应测试均失败；在 `Sources/NoemaIME` 注入 `import NoemaClipboardCore` 与 `AXIsProcessTrusted()`，`check-imports.sh` 退出 1。
- 风险：来源 App 取的是检测到变化时的前台 App，后台 App 写剪贴板会被记到前台 App 名下；安全输入在 400 ms 轮询间隙内开启又关闭时，那次复制仍可能被记录（只有未标记的内容）；首次读取时系统按 `accessBehavior` 询问，用户选择拒绝后面板显示横幅、不再读取；ad-hoc 重签名后钥匙串可能弹出访问确认，拒绝即进入 `.keychainLocked`。启发式敏感识别必然有漏判，但所有条目都已加密。全局 `⇧⌘V` 会盖过多数 App 的“粘贴并匹配样式”；被其他 App 占用时注册失败，面板仍可从菜单栏与 `v2` 打开。
